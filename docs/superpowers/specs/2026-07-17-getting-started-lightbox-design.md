# Getting Started GIF Lightbox — Design Spec

**Date:** 2026-07-17
**Status:** Approved

## Purpose

The How It Works page's "Getting Started" GIF (`public/getting-started.gif`) is currently a plain, small, static `<img>` — hard to read at its inline size. Add click-to-zoom so users can view it larger. The GIF itself will be separately regenerated by the user (via the existing `npm run capture:demo` script) to reflect the recent sidebar color change (`#17225a`) — out of scope for this spec.

## Current State

`src/pages/HowItWorks.tsx` lines 132-153: the "Getting Started" card renders the GIF as a static `<img>` with no click handler, no cursor affordance, and no enlarged view. Confirmed via code read — no existing zoom/lightbox behavior anywhere in this file.

## Design

Add lightbox state and a full-screen overlay, implemented inline in `HowItWorks.tsx` (no new file — this is a single-use, self-contained bit of UI, consistent with how `BrandTabsModal` is the only extracted modal in this file and everything else stays inline).

**Trigger:**
- `const [showGifLightbox, setShowGifLightbox] = useState(false)` alongside the existing `showBrandTabsModal` state.
- The `<img>` becomes a `<button type="button" onClick={() => setShowGifLightbox(true)}>` wrapper (or `onClick` directly on the `<img>` with `role="button"` semantics via a wrapping button for a11y/keyboard support).
- Add `cursor-pointer` and a hover affordance (e.g. `hover:opacity-90 transition-opacity`) so it visibly reads as clickable. No permanent zoom-icon overlay needed — hover state is enough.

**Lightbox overlay** (rendered conditionally at the bottom of the component, alongside the existing `{showBrandTabsModal && <BrandTabsModal .../>}` line):
- `fixed inset-0 z-50 flex items-center justify-center p-4` wrapper.
- Backdrop: `absolute inset-0 bg-black/70`, `onClick` closes.
- Enlarged GIF: same `/getting-started.gif` src, `max-w-4xl max-h-[85vh] w-full rounded-lg` (or similar), centered, `onClick` on the image itself does *not* close (stop propagation) so clicking the image isn't mistaken for backdrop-dismiss.
- Close (X) button top-right of the image, using the same icon/style convention as `BrandTabsModal`'s close button (`X` from `lucide-react`).
- **Escape-to-close:** use `BrandTabsModal`'s working pattern — a `useEffect` with a `document.addEventListener('keydown', ...)` listener checking `e.key === 'Escape'`, NOT the broken focus-dependent pattern used by `TotalBreakdownModal`/`AddReviewAccountModal`/`EditEntryModal` (per prior project notes on that bug).

## Explicitly Unchanged

- The GIF file itself (`public/getting-started.gif`) — regeneration is the user's separate manual step.
- The inline (non-zoomed) size/position of the GIF in the "Getting Started" card layout.
- The step list (`GETTING_STARTED_STEPS`) and its styling.
- No new dependencies — `lucide-react`'s `X` icon is already used elsewhere in this codebase (e.g. `BrandTabsModal`).

## Testing / Verification

- `npm run build` must pass.
- Manual check via `npm run dev`: click the GIF opens the lightbox enlarged and centered; clicking the backdrop, the X button, and pressing Escape all close it; clicking the enlarged GIF itself does not close it.
